sign (Java) — генератор CAdES-подписи боевым ключом (для фикстур/проверок)

использование: sign [опции] <файл>
       sign [опции] <cms-файл>          (co-sign — файл уже CAdES, см. ниже)
       sign --add tsp|ocsp|tsp-ocsp|archive|chain [--force] [--index N|all]
            [--out PATH] <файл>
       sign --strip tsp|ocsp|archive|archive-all|unsigned [--index N|all]
            [--out PATH] <файл>
       sign --sort-signer-infos time|der [--out PATH] <файл>

  --mode MODE       attached (по умолчанию, eContent внутри CMS) | detached —
                    только при первом подписании; co-sign сам определяет режим
                    по структуре существующего контейнера, --mode для него ошибка
  --document PATH   байты подписанного документа — нужен ТОЛЬКО для co-sign
                    detached-контейнера (в нём самом eContent нет)
  --out PATH        путь к выходному CMS (по умолчанию tmp/cades_blt_<ts>.cms,
                    либо <файл>_augmented.cms/_stripped.cms/_fullchain.cms/
                    _archived.cms — в зависимости от режима)
  --fullchain       вложить в CMS.certificates всю цепочку до самоподписанного
                    корня (КУЦ) включительно, а не только серт подписанта (при
                    co-sign — цепочка НОВОГО подписанта)
  --strict-blt      полное соответствие ETSI EN 319 122-1 §6.3: + OCSP на
                    сертификат TSA (внутри самого TST) и полные цепочки не
                    только подписанта, но и OCSP-ответчика/TSA (без дублей);
                    при первом подписании или co-sign — для НОВОЙ подписи
  --key P12_FILE    явный путь к P12-ключу (иначе — автопоиск единственного
                    файла в .keys/valid/)

  --add tsp         добавить signature-time-stamp (TSA) — только если его не было
  --add ocsp        добавить revocation-values (OCSP) — только если её не было
  --add tsp-ocsp    добавить оба атомарно — только если ОБОИХ не было изначально
  --add archive     добавить archive-time-stamp-v3 к готовому CAdES-B-LT
  --add chain       добавить цепочку (УЦ + КУЦ) в CMS.certificates
  --force           с --add tsp|ocsp|tsp-ocsp — снести уже существующий атрибут
                    и вписать свежий, даже если он уже был

  --strip tsp           удалить signature-time-stamp, если он был
  --strip ocsp          удалить revocation-values, если она была
  --strip archive       удалить ПОСЛЕДНЮЮ archive-time-stamp-v3
  --strip archive-all   удалить ВСЕ archive-time-stamp-v3
  --strip unsigned      удалить unsignedAttrs целиком
  --strip signature     удалить ОДНУ подпись целиком (требует --index N —
                        конкретный номер, --index all не поддерживается);
                        если подпись в файле только одна, не трогает файл

  --index N         с --add/--strip — только подписант с этим индексом (0-based,
                    файловый порядок — тот же index, что в JSON eds-check); без
                    --index операция применима только к файлу РОВНО с одной
                    подписью, иначе ошибка с подсказкой (--strip signature —
                    --index N обязателен всегда)
  --index all       с --add/--strip (кроме --strip signature) — сразу все
                    подписанты, АТОМАРНО: guard-блок (архивная метка и т.п.)
                    хотя бы у ОДНОГО — отказ всего запроса, файл не пишется;
                    идемпотентный no-op у части подписантов остальным не мешает

  При наличии хотя бы одной archive-time-stamp-v3 У ЦЕЛЕВОГО подписанта
  разрешены только --add archive, --strip archive[-all] и --strip unsigned —
  остальные --add/--strip этого подписанта не трогают (метка защищает его
  unsignedAttrs целиком, ETSI EN 319 122-1 §5.5.2), с выводом сообщения.

  --sort-signer-infos time   переставить блоки SignerInfo по возрастанию genTime
                             TSA-метки (подписи без метки — в хвост, в исходном
                             относительном порядке)
  --sort-signer-infos der    переставить блоки SignerInfo в канонический порядок
                             SET OF (ITU-T Rec. X.690 §11.6 / ISO/IEC 8825-1),
                             независимо от времени. --index после сортировки
                             может указывать на другого подписанта; безопасно и
                             для архивированного файла — порядок SignerInfo не
                             входит ни в чью archive-time-stamp-v3

  --lang ЯЗЫК       ru (по умолчанию) — язык вывода
  -h, --help        показать эту справку и выйти

  файл              подписываемый документ (первое подписание), ЛИБО уже готовый
                    CMS — обычный запуск тогда добавляет ЕЩЁ ОДНУ подпись
                    (co-sign), а --add/--strip меняют его unsignedAttrs
